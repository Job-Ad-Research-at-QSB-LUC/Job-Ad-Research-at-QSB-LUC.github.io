Term convention. Review-retained means both Claude Sonnet 4.6 and GPT-4o judged an unlisted occupation-task pair as a YES under the review prompt. Canonical O*NET-listed pairs are retained separately. Some files keep older validated or agreement_retained names for compatibility.

What differs from the posting-derived map?

O*NET and postings cover nearly the same occupations, but wire them differently. In the audited comparison, only 7.9% of occupation links appear in both maps. About 41.2% of posting-derived links are also O*NET shared-DWA links, far above a degree-preserving null, so the posting map is anchored in real task/activity overlap rather than arbitrary noise.

But O*NET remains more aligned with the SOC hierarchy: 58.2% of O*NET shared-DWA edges cross SOC-2 major groups, compared with 76.9% of posting-derived edges. O*NET communities almost reproduce SOC-2 groups, while posting-derived communities cut across them more often.

Substantively, the posting map puts more weight on cross-major movement into management, business, office, sales, and computer-related work. The O*NET-native map retains more within-family structure, especially where curated task and activity language is occupation-specific.

Why this matters

The task map does not only add technical tasks to technical occupations. It also shows interpersonal, coordination, and management tasks flowing into occupations often treated as highly exposed to AI.

In the recreated diagnostic, 522 posting-confirmed task migrations into SOC-15/17 meet this filter: 422 are non-routine interpersonal and 100 are admin/management. This is a narrow example, not a complete occupational profile, but it illustrates why posting-derived maps can qualify exposure measures built only from canonical task assignments.

The evidence supports a modest claim: technical occupations may combine frontier technical work with human coordination tasks that standard task homes do not fully show. It does not imply those occupations are insulated from AI adoption.

JAAT links job-ad text to standard O*NET task IDs and occupational codes, producing many-to-many occupation-task evidence from postings. O*NET supplies occupation-specific task assignments; posting-derived pairs can therefore reveal plausible task assignments outside the standard model. Finding 1 answers whether these non-canonical posting-derived pairs are viable rather than arbitrary.

The explorer shows the canonical O*NET home for a selected task alongside newly retained posting occupations. The manuscript figure uses a static worked example; the dashboard keeps the same logic interactive and defaults to a task with at least two new retained occupations.

Two-model rule. On the dashboard, canonical O*NET-listed pairs are retained. Unlisted pairs are retained only when both models return a strict (unanimous) YES verdict for the occupation-task pair. A same verdict means both models agree on YES or both agree on NO; it is reported separately from the unanimous YES pass rule.
